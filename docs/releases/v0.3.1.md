# tuohi v0.3.1

This patch release fixes the default background of Windows views. It changes
no API. Go 1.26 remains the minimum; shipped code builds with
`CGO_ENABLED=0`.

```sh
go get github.com/terva-sh/tuohi@v0.3.1
```

## Fix

- On Windows, tuohi never set WebView2's default background: it asked for
  `ICoreWebView2Controller2` with the wrong interface ID, so the request
  always failed with `E_NOINTERFACE`. Kuiske found it. The ID now matches
  Microsoft's `WebView2.h`, which every other ID tuohi uses already matched.
  The colour tuohi meant as opaque white was in fact opaque black: the
  `{A, R, G, B}` bytes were packed the wrong way round. That is fixed as
  well.

## Behaviour to review

**Windows now does what `View.Frame` documents.** A framed window paints
opaque white behind the page. A frameless window, which is the default, is
transparent wherever the page does not paint, so the desktop shows through,
as it already does on WebKitGTK and WKWebView. Until now Windows showed
WebView2's white there. A frameless application whose page sets no
background of its own will see the desktop through it after this release;
give the page a background, or use `View.Frame`, to keep an opaque window.

## Validation

A native Windows test asks a live WebView2 controller for
`ICoreWebView2Controller2`, which the old ID could not obtain, and reads back
the colour of a framed and a frameless view. It passed on GitHub's Windows
runner in [run 40056863061](https://github.com/terva-sh/tuohi/actions/runs/40056863061),
together with every other test, lint and build job. A unit test checks the
colour packing.

The limits in the [v0.3.0 notes](v0.3.0.md) and the [desktop acceptance
record](../desktop-acceptance.md) are unchanged, except that the Windows
default background is no longer a known problem.
