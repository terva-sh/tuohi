# tuohi v0.2.0

This source release adds optional desktop services for applications that need
interactive notifications, changing tray state, retained windows and signed
self-updates. Existing static tray configurations, notification helpers and
normal window-close behavior keep their defaults. Go 1.26 remains the minimum;
shipped code builds with `CGO_ENABLED=0`.

```sh
go get github.com/terva-sh/tuohi@v0.2.0
```

## New APIs

- [Managed notifications](../../notify/README.md): `notify.NewClient` returns
  correlated handles with activation, replacement, dismissal and explicit
  permission query/request. Opaque application IDs stay in the Go process;
  consumers own notification text and privacy. Linux binds to one daemon
  lifetime, including activation of an installed on-demand service. macOS uses
  `UNUserNotificationCenter` and requires a properly identified `.app` and an
  available notification-center delegate. **Managed Windows notifications are
  unsupported**; legacy notification helpers retain their behavior.
- [Runtime tray state](../../tray/README.md): `tray.Update` patches icon
  variants, tooltip and menu items, including checked/disabled state, without
  recreating the tray. Availability snapshots and callbacks expose registration
  and host loss/return. Registration does not prove that an icon is visible or
  usable; the consumer decides whether hiding its only window is safe.
- [Window lifecycle](../../README.md#window-close-and-native-state):
  `View.CloseRequested`, `CloseRequest` and `View.RequestClose` allow cancellation
  or deferral of user close requests while retaining the renderer.
  `View.WindowChanged` and `WindowState` expose native visibility/activation.
  Callbacks run on the UI thread. Unconditional `View.Close` and `App.Quit`
  invalidate deferred requests so they cannot trap normal shutdown.
- `App.OpenExternal` replaces system-browser handoff for that application,
  including `App.Open` and refused/outside navigations. It enables consumer tests
  without a mutable global hook or weaker navigation policy.
- [Desktop updates](../../updater/README.md): verify bounded Ed25519-signed
  manifests, stage size/hash-checked artifacts, then explicitly schedule portable
  executable or whole-macOS-bundle replacement after graceful shutdown. Helpers
  support restart and recovery. Applications supply transport, pinned keys,
  consent, channel and normal shutdown; package/store-managed installations use
  their existing update mechanism. No updater is enabled automatically.

See the public-API examples for [notifications](../../examples/managednotify/),
[tray updates](../../examples/tray/), [window lifecycle](../../examples/lifecycle/),
[update installation](../../examples/selfupdate/) and
[offline metadata signing](../../examples/updatefeed/).

## Fixes and behavior to review

- GTK3 app-region maximize toggling now restores the window on the next toggle;
  a real window-manager regression covers repeated maximize/restore cycles on
  both GTK stacks.
- Windows single-instance handoffs preserve messages buffered before the server
  starts, with a native regression.
- macOS enables the public element-fullscreen preference, correcting a later
  contradictory disable and implementing the selected parity with the other
  engines. Fullscreen remains subject to engine availability and gesture rules;
  it is outside `View.Permissions`.
- [Navigation security](../navigation-security.md) now states WebView2's request
  limit explicitly: cancelling `NavigationStarting` retains the current
  document but may occur after an HTTP GET starts. `View.Origins` governs
  document/bridge trust and does not implement a network firewall.

## Validation and limits

The [desktop acceptance record](../desktop-acceptance.md) separates cgo-free
native CI, compilation and consumer execution from the remaining manual checks.
The release workflow gates publication on Linux, macOS and Windows tests, lint
and the example-build matrix. FreeBSD and NetBSD have compilation coverage,
without native runtime acceptance here. This library release has no desktop
binaries or consumer update feed.

Kuiske's production executable has passed actual Xfce panel and GNOME Keyring
checks on both Linux engines in an isolated X11/Xvfb session. This does not
establish physical desktop/Wayland usability, WSLg, Steam Frame, real-daemon
message delivery with enrolled accounts, interactive packaged macOS notification
behavior, or production team-signed bundle update/rollback/relaunch. Those
checks remain open; hosted CI and helper fixtures do not replace them.

Existing runtime investigations also remain open: WebKitGTK 4.1 2.54.0 can crash
on an allowed read of an unowned X11 clipboard, and an older WebView2 runtime
occasionally dropped a `data:` page's binding message. Neither is claimed fixed
by this release. Intermittent GTK4 test navigation stalls also remain under
investigation; successful repeats do not establish a fix. Prefer a current
engine, and retain the documented permission and navigation boundaries.
